# MPI

> 分散メモリ環境で動作する並列プログラムのために、プロセス間のメッセージ通信を定めた標準規格であり、HPCにおける並列プログラミングの事実上の標準である。

## 概要
MPI（Message Passing Interface）は、MPI Forumが策定するライブラリインタフェースの規格である。1994年にMPI-1.0が公開された。その後、MPI-2.0（1997年）で片側通信や[[MPI-IO]]が、MPI-3.0（2012年）でノンブロッキング集団通信などが追加され、現行版はMPI-5.0（2025年）である。規格が定めるのはC言語とFortranから呼び出す関数の仕様であり、実装は複数存在する。代表的なものに、[[MPICH]]、[[Open MPI]]、およびそれらを基にしたベンダ実装がある。

MPIのプログラムは、通常、同一のプログラムを多数のプロセスとして同時に起動するSPMD（Single Program, Multiple Data）の形式を採る。各プロセスは独立したアドレス空間を持ち、他のプロセスのメモリを直接参照できないため、データの受け渡しはすべて明示的な通信で行う。プロセスの集合はコミュニケータで表され、全プロセスを含む `MPI_COMM_WORLD` の中で、各プロセスはランクと呼ばれる0から始まる番号で識別される。プログラムは自身のランクに応じて担当するデータや処理を切り替える。プログラムは `mpiexec` や `mpirun`、あるいはジョブスケジューラの起動コマンド（[[Slurm]]の `srun` など）で、指定した数のプロセスとして起動される。

通信は大きく三種類に分かれる。一対一通信は、`MPI_Send` と `MPI_Recv` のように送信側と受信側のプロセスが対になって行う通信である。`MPI_Isend`・`MPI_Irecv` のようなノンブロッキング版は、通信の完了を待たずに戻り、後で `MPI_Wait` などにより完了を確認する。これにより通信と計算を重ね合わせることができる。[[Collective Communication|集団通信]]は、コミュニケータ内の全プロセスが参加する通信である。`MPI_Bcast`（一つのプロセスから全員への配布）、`MPI_Reduce`・`MPI_Allreduce`（全員の値の総和などの集約）、`MPI_Alltoall`（全員が全員とデータを交換）などがある。片側通信（RMA）は、他のプロセスが公開したメモリ領域に対して、相手の明示的な受信操作なしに読み書きする方式である。

## どこで出てくるか
スーパーコンピュータ上の大規模なシミュレーションの多くはMPIで書かれており、ノード間の並列化はMPI、ノード内のスレッド並列化は[[OpenMP]]、という組み合わせ（ハイブリッド並列）が一般的である。MPIの実装は、[[InfiniBand]]などの高速ネットワークと[[RDMA]]を用いて低遅延・高帯域の通信を実現しており、その性能はアプリケーション全体の性能を大きく左右する。並列プログラムの性能分析では、計算時間と通信時間の比率や、集団通信が全プロセスの同期点となって生じる待ち時間が主要な論点となる。I/Oについては、MPIの規格の一部である[[MPI-IO]]が、多数のプロセスから[[Access Pattern|共有ファイル]]へ効率よく読み書きするための手段を提供し、[[Parallel File System|並列ファイルシステム]]の性能を引き出す上で重要な役割を果たす。
