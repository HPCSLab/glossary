# File Descriptor（ファイルディスクリプタ）

> プロセスがオープン中のファイルを識別するための、プロセスごとに一意な非負整数である。

## 概要
[[open|open()]] が成功すると、カーネルは「そのファイルにどうアクセスしているか」を記録するオープンファイル記述（open file description）を新たに作成し、それを指す整数をファイルディスクリプタとして返す。以後の [[read|read()]]・[[write|write()]]・[[close|close()]] などはファイル名ではなくこの整数を引数に取る。[[POSIX]]は、新たに割り当てる番号を未使用のうち最小のものと定めている。慣例として 0・1・2 は標準入力・標準出力・標準エラー出力に割り当てられているため、プロセスが最初に開いたファイルは通常 3 となる。

オープンファイル記述は、ファイルオフセット、アクセスモード（読み取り専用・書き込み専用・読み書き）、`O_APPEND` などのファイル状態フラグを保持する。ファイルオフセットは次のI/Oを開始するバイト位置であり、`open()` 直後はファイルの先頭を指す。`write()` はこのオフセットの位置からデータを書き込み、成功して戻る前に、実際に書き込んだバイト数だけオフセットを進める。`read()` も同様に、読み込んだバイト数だけオフセットを進める。したがって、同じディスクリプタに対して `write()` を繰り返すと、データは前回の続きに順に書き込まれる。オフセットは [[lseek|lseek()]] で明示的に変更できる。

この基本動作には、二つの例外がある。第一に、`O_APPEND` を指定して開いた場合、各 `write()` の直前にオフセットがファイル末尾へ設定され、その設定と書き込みの間に他のファイル変更操作が割り込まないことが保証される。第二に、`pread()`・`pwrite()` は引数で指定した位置に対してI/Oを行い、ディスクリプタのオフセットを変更しない。

ディスクリプタとオープンファイル記述は一対一とは限らない。`dup()` で複製したディスクリプタや、`fork()` で子プロセスに継承されたディスクリプタは同一のオープンファイル記述を指すため、オフセットを共有する。一方、同じファイルを `open()` で二度開けば、それぞれ独立したオープンファイル記述とオフセットを持つ。

## どこで出てくるか
並列アプリケーションが一つの共有ファイルに書き込む場合、各プロセスが独立に `open()` して自分の担当領域へ `lseek()` してから書くか、`pwrite()` で位置を直接指定するのが基本形である。オフセットを共有する状態で複数の書き込み主体が `write()` を発行すると、書き込み位置が実行順序に依存して予測できなくなる。ログファイルのように末尾へ追記していく用途では `O_APPEND` が用いられる。また、プロセスが同時に開けるディスクリプタ数には上限があり、大量のファイルを扱うプログラムでは「Too many open files」というエラーとしてこの上限に直面する。
