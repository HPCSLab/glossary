# Distributed File System（分散ファイルシステム）

> 複数の計算機から、ネットワークのプロトコルを介して、同じファイルを通常のファイルの操作で読み書きできるようにするファイルシステムである。

## 概要
複数の計算機から同時にマウントされて共有されるファイルシステムには、二つの方式がある。一つは共有ディスク方式であり、[[iSCSI|SAN]]などを介して各計算機が同じ記憶装置にブロックの単位で直接アクセスし、同じファイルへの同時アクセスを調停する仕組みを持つ。もう一つが分散ファイルシステムであり、記憶装置へのブロック単位のアクセスは共有せず、サーバとクライアントの間のネットワークのプロトコルによってファイルを読み書きする。

分散ファイルシステムは、リモートのファイルをローカルのファイルと同じ[[System Call|システムコール]]で扱えること（アクセスの透過性）、どの計算機からも同じ名前空間が見えること（位置の透過性）、複数のクライアントが一貫した状態を見られること、サーバの故障の後も動作を続けられることを目標とする。ただし、ネットワークの遅延の下で複数のクライアントのキャッシュの一貫性を保つことは難しい。[[NFS]]のclose-to-open一貫性のように、[[POSIX]]の意味論を緩めた実装もある。

分散ファイルシステムのうち、データを多数のサーバに分散して置き、並列に読み書きすることで高い性能を得るものを[[Parallel File System|並列ファイルシステム]]と呼ぶ。

## どこで出てくるか
計算機センターのホームディレクトリはNFSなどで、大規模な計算の入出力は[[Lustre]]や[[IBM Storage Scale]]などの並列ファイルシステムで共有される。いずれも、どのノードからも同じパスで同じファイルが見えるが、ローカルの[[File System|ファイルシステム]]とは性能も一貫性の保証も異なる。ストレージの研究では、[[Metadata|メタデータ]]の処理の分散や、一貫性の緩和による性能の向上が主要な論点である。
