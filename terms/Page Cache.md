# Page Cache（ページキャッシュ）

> OSカーネルが、ファイルのデータを主記憶上にページ単位で保持し、記憶装置へのアクセスを肩代わりするキャッシュである。

## 概要
Linuxでは、通常の[[read]]・[[write]]・[[mmap]]はすべてページキャッシュを経由し、アプリケーションが記憶装置に直接アクセスすることはない。`read()` は、対象のページがキャッシュにあれば記憶装置にアクセスせずに主記憶から複製して返し、なければ記憶装置から読み込んでキャッシュに格納した後に返す。キャッシュ上のページは、ファイルごとに[[address_space]]で管理される。順次読み込みが検出されると、後続のページを先回りして読み込む先読み（readahead）も行われる。

`write()` は、データをキャッシュ上のページに複製し、そのページを「ダーティ」（記憶装置と内容が異なる状態）として印を付けた時点で戻る。ダーティページは、カーネルのフラッシャスレッドによって後から非同期に記憶装置へ書き戻される（ライトバック）。書き戻しは、ダーティデータが一定時間を経過したとき、あるいはダーティページの量が主記憶に対する一定の割合を超えたときに始まる。さらに上限の割合を超えると、書き込みを行ったプロセス自身が書き戻しを待たされる。これらの閾値は `/proc/sys/vm/` 以下の `dirty_*` パラメータで調整できる。アプリケーションが書き戻しの完了を確認するには[[fsync]]を用いる。

ページキャッシュは空いている主記憶を積極的に使い、メモリが必要になると、ダーティでないページから順に解放される。`free` コマンドの `buff/cache` 欄はこの使用量を示し、数値が大きくてもメモリ不足を意味しない。[[open]]に `O_DIRECT` を指定すると、ページキャッシュを迂回して記憶装置と直接データを転送できる（[[Direct IO|Direct I/O]]）。ただし、これはLinux独自の拡張であり、バッファのアドレスやサイズ、オフセットに整列（アライメント）の制約が課されることがある。

## どこで出てくるか
I/O性能を計測する際、ページキャッシュの影響は最も注意すべき要因である。直前に読んだファイルの再読み込みは主記憶の速度で完了し、`write()` の時間はキャッシュへの複製の時間にすぎないことが多い。そのため、記憶装置そのものの性能を測るには、主記憶より大きいデータを用いる、`O_DIRECT` を使う、計測前に `sync` を実行してから `/proc/sys/vm/drop_caches` に書き込みキャッシュを破棄する、`fsync()` を計測に含める、などの対策が必要となる。`drop_caches` はダーティページを解放しないため、事前の `sync` が推奨されている。

データベースなど独自のキャッシュを持つソフトウェアは、二重のキャッシュを避けるために `O_DIRECT` を用いることがある。また、[[Parallel File System|並列ファイルシステム]]のクライアントもノードごとにページキャッシュを持つため、複数ノード間でキャッシュの内容を整合させることが、[[POSIX]]の一貫性を満たす上での課題となる。
