# Weak Scaling（弱スケーリング）

> プロセスあたりの問題の大きさを固定し、プロセス数に比例して全体の問題を大きくしたときに、実行時間がどれだけ一定に保たれるかを評価する方法である。

## 概要
弱スケーリングでは、プロセス数を2倍にすると全体の問題の大きさも2倍にするため、各プロセスが担当する仕事の量は変わらない。理想的には、実行時間はプロセス数によらず一定となる。結果は、横軸にプロセス数、縦軸に実行時間を取ったグラフで示すことが多く、理想的な場合は水平な直線となる。[[Parallel Efficiency|並列化効率]]は $E(N) = T(1) / T(N)$ で評価する。

弱スケーリングの考え方は[[Gustafson's Law|グスタフソンの法則]]に基づく。問題を大きくしても逐次部分の時間が増えない限り、並列部分の割合が増すため、プロセス数に比例した速度向上（同じ時間でより大きな問題を解けること）が期待できる。ただし、実際には全プロセスが参加する[[Collective Communication|集団通信]]や同期のコストがプロセス数とともに増大し、効率を低下させる。また、全体の問題が大きくなるにつれて、入出力するデータの量も増えるため、[[Parallel File System|並列ファイルシステム]]へのI/Oがボトルネックとなることもある。

## どこで出てくるか
弱スケーリングは、計算資源を増やすことで、より大規模・高解像度の問題を同じ時間で解きたい場合の指標である。単一のノードのメモリに収まらない大規模シミュレーションが典型例である。弱スケーリングの効率が高いことは、プログラムがより大きな計算機でも有効に動作することを示す根拠となる。一方、強スケーリングの効率が低いプログラムでも弱スケーリングの効率は高いことがよくあるため、性能を報告する際には、どちらの方法で測定したかを明示する必要がある。
