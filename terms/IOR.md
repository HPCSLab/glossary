# IOR

> 多数のプロセスから並列にファイルを読み書きし、様々なインタフェースとアクセスパターンで並列ストレージシステムの性能を測るベンチマークである。

## 概要
IORは、[[MPI]]で起動した多数のプロセスに同時に読み書きを行わせ、その帯域を測る並列I/Oのベンチマークであり、プロセス間の同期にMPIを用いる。同じリポジトリには、メタデータの性能を測る[[mdtest]]も含まれている。

I/Oのインタフェースは `-a` で選び、[[POSIX]]、[[MPI-IO]]、[[HDF5]]、S3、PnetCDF（NCMPI）、Cephのライブラリ（RADOS）などを用いられる。アクセスパターンは主に次のオプションで指定する。

| オプション | 意味 |
|---|---|
| `-b` | 各プロセスが連続して書き込むバイト数（ブロックの大きさ） |
| `-t` | 一回のI/Oの呼び出しで転送するバイト数 |
| `-s` | ファイル中のセグメントの数。セグメントは、複数のプロセスがアクセスする連続した領域である |
| `-F` | 各プロセスが別々のファイルに読み書きする（指定しない場合は全プロセスで一つの共有ファイル） |
| `-z` | ファイル内のアクセスの位置を無作為にする |
| `-c` | 対応するインタフェースで集団的I/Oを用いる |
| `-e` | POSIXのファイルを閉じた後に[[fsync]]を行う |
| `-C` | 読み込みの際に、各プロセスが別のノードのプロセスの書いたデータを読むよう順序を入れ替える |
| `-w` / `-r` / `-i` | 書き込み、読み込みの実行と、繰り返しの回数 |

`-F` の有無によって、[[Parallel File System|並列ファイルシステム]]でよく比較される、プロセスごとに別のファイルに書く方式（N-N）と、全プロセスで一つのファイルに書く方式（N-1）を切り替えられる。

## どこで出てくるか
IORは、[[IO500]]の構成要素でもある。結果を解釈する際に最も注意すべきは、[[Page Cache|ページキャッシュ]]の影響である。書き込んだ直後に同じノードで読み込むと、データはそのノードのメモリから返されるため、ファイルシステムの実際の性能より大幅に高い値が得られてしまう。`-C` を指定すれば、各プロセスは別のノードが書いたデータを読むため、ページキャッシュが効かず、ファイルシステムから読み込まれる。同様の理由で、書き込むデータの総量が、キャッシュに使えるメモリの量に比べて十分に大きいかどうかも、測定値の意味を左右する。書き込みの性能についても、`-e` でfsyncを含めるかどうかで、測っているものが異なる。
