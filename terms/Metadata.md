# Metadata（メタデータ）

> データそのものではなく、データについての情報であり、ファイルシステムでは、ファイルの名前、属性、配置、ディレクトリの構造などを指す。

## 概要
[[File System|ファイルシステム]]のメタデータには、ファイルの種類、権限、所有者、サイズ、タイムスタンプなどの属性、データが記憶装置上のどこにあるかを示す配置の情報、そして名前からファイルの実体への対応を表すディレクトリの構造がある。Unix系のファイルシステムでは、属性と配置の情報は[[Inode|inode]]に、名前の対応はディレクトリのエントリに格納される。このほか、空き領域の管理情報や、ファイルシステム全体の情報を持つ[[Superblock|スーパーブロック]]もメタデータに含まれる。

ファイルの内容を読み書きする操作（[[read]]、[[write]]）に対し、メタデータを読み書きする操作をメタデータ操作と呼ぶ。ファイルの作成と[[open]]、[[stat]]、ディレクトリの一覧の取得、[[unlink]]、[[rename]]、権限の変更などがこれに当たる。メタデータ操作は、一回あたりに扱うデータ量が小さい一方、名前の探索、権限の検査、複数の構造の不可分な更新、[[Crash Consistency|クラッシュ整合性]]の確保を伴う。そのため、性能は転送量ではなく、一秒あたりに処理できる操作の回数と[[Latency|レイテンシ]]で評価される。

## どこで出てくるか
HPCのストレージでは、メタデータの性能がしばしばボトルネックとなる。[[Parallel File System|並列ファイルシステム]]は、データを多数のサーバに分散してデータの[[Bandwidth|帯域]]を拡大するが、名前空間とメタデータは少数のメタデータサーバで管理することが多い。そのため、多数のプロセスが同時にファイルを作成する、小さなファイルを大量に読み書きする、`ls -l` や `find` で大きなディレクトリを走査する、といった操作は、メタデータサーバに負荷を集中させ、システム全体の性能を低下させる。[[Lustre]]の[[DNE]]のようにメタデータを複数のサーバに分散する仕組みや、小さなファイルのデータをメタデータサーバに置くDoMの仕組みは、この問題への対処である。研究では、既存のファイルシステムの上でメタデータを多数のサーバに分散する[[IndexFS]]などが提案されている。

利用者の側でも、ファイル数を抑える工夫が性能に直結する。プロセスごとに大量の小さなファイルを作る代わりに、[[HDF5]]などの形式で一つのファイルにまとめる、アーカイブにまとめて展開せずに読む、などの方法がとられる。メタデータの性能は[[mdtest]]などのベンチマークで、データの帯域は[[IOR]]で測定され、両者は並列ファイルシステムの性能を評価する二本柱となっている。分散ストレージの設計では、メタデータの管理をどこに置き、どう分散し、どの程度の一貫性を保証するかが、システムの拡張性を左右する中心的な論点である。
