# Virtual Memory（仮想記憶）

> 各プロセスに、物理メモリとは独立した専用のアドレス空間を与え、その仮想アドレスを、OSとハードウェアが協調して物理メモリ上の位置に対応付ける仕組みである。

## 概要
仮想記憶のもとでは、プロセスが扱うアドレスはすべて仮想アドレスであり、物理メモリ上の実際の位置（物理アドレス）とは異なる。各プロセスは自分専用のアドレス空間を持つため、他のプロセスのメモリを誤って、あるいは故意に書き換えることはできない。また、物理メモリ上で連続していない領域を、仮想アドレス空間上では連続した領域として見せられる。

対応付けは、ページと呼ばれる固定長の単位（x86-64では通常4KiB）で行われる。仮想ページと物理ページの対応は、カーネルが管理するページテーブルに記録される。ページテーブルは多段の木構造であり、Linuxは最大5段（PGD、P4D、PUD、PMD、PTE）の構造を扱う。アドレスの変換は、CPU内のMMU（メモリ管理ユニット）がページテーブルをたどって行い、その結果はTLB（Translation Lookaside Buffer）と呼ばれる小さなキャッシュに保持される。TLBに対応が見つからない場合は、ページテーブルをたどり直す必要があるため、メモリアクセスが遅くなる。2MiBや1GiBの大きなページ（ヒュージページ）を用いると、一つのTLBの項目で広い範囲を変換できるため、大量のメモリを扱うプログラムでTLBの不足を緩和できる。

アクセスしたページに有効な対応がない場合、CPUはページフォルトを発生させ、カーネルに処理を移す。カーネルは、それが正当なアクセスであれば、物理ページを割り当てる、ファイルの内容を読み込む、コピーオンライトで複製を作るなどの処理を行い、ページテーブルを更新してから命令を再実行させる。正当でなければ、プロセスにセグメンテーション違反（SIGSEGV）を通知する。この仕組みにより、メモリは実際にアクセスされた時点で初めて割り当てられ（要求時ページング）、[[mmap]]によるファイルの写像や、`fork()` 時のメモリのコピーオンライトによる共有が実現される。物理メモリが不足すると、使われていないページを記憶装置のスワップ領域に退避し、その物理ページを他の用途に回すこともできる。

## どこで出てくるか
仮想記憶は、[[mmap]]、[[Page Cache|ページキャッシュ]]、プロセスの生成、メモリの確保など、OSの多くの機能の土台である。性能の面では、ページフォルトとTLBミスが問題となる。大きな配列を初めて触れる際には、ページごとにページフォルトが起きるため、初期化の時間が計測に混入しないよう注意を要する。ランダムなアクセスが広い範囲に及ぶプログラムでは、TLBミスが多発し、ヒュージページの使用が有効な場合がある。複数のCPUソケットを持つ計算機では、物理ページがどのソケットのメモリに割り当てられるか（NUMA）も性能に影響する。[[perf]]を用いると、ページフォルトやTLBミスの回数を計測できる。また、スワップが発生すると、メモリアクセスが記憶装置へのI/Oに置き換わり、性能が桁違いに低下する。
