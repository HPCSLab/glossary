# HDF5

> 大規模で複雑な科学技術データを、多次元配列とその説明を階層的に整理して一つのファイルに格納するための、データモデル、ファイル形式、ライブラリの総体である。

## 概要
HDF5は、The HDF Groupが開発・保守している。HDF5という名称は、三つのものを合わせて指す。データを論理的に整理するためのデータモデル、それをファイルに格納する形式、そしてそれを読み書きするライブラリとツールである。ライブラリはC言語で実装され、C++、Fortran、Java、Pythonなどから利用できる。Pythonからはh5pyを用いるのが一般的である。

データモデルの中心は、グループとデータセットである。グループはディレクトリに相当し、他のグループやデータセットを入れ子に含む。ファイルは必ずルートグループ `/` を持ち、各オブジェクトは `/simulation/step0001/temperature` のようなパスで指定される。データセットは、要素の型（データ型）と形状（データ空間）を持つ多次元配列である。グループとデータセットには、単位や作成条件などの説明を属性（名前と値の組）として付けられる。データ自身がその構造と意味の説明を含むため、HDF5は自己記述的な形式と呼ばれる。

データセットの格納方式は性能に直結する。既定の連続配置のほかに、配列を固定の大きさのブロック（チャンク）に分割して格納するチャンク配置を選べる。チャンク配置では、配列の一部分だけを効率よく読み書きでき、大きさを後から拡張でき、チャンクごとに圧縮フィルタを適用できる。一方、チャンクの大きさがアクセスの仕方に合っていないと、不要なデータの読み込みや展開が大量に発生する。読み書きでは、データ空間の一部を範囲や間隔で指定するハイパースラブ選択により、配列の任意の部分を対象にできる。

並列環境向けには、Parallel HDF5が提供されている。これは下位層に[[MPI-IO]]を用い、複数の[[MPI]]プロセスが一つのHDF5ファイルを共有して読み書きできるようにする。ファイルの構造やメタデータを変更する操作（グループやデータセットの作成など）は全プロセスが参加する集団操作として行う必要があり、データの書き込みは独立にも集団的にも行える。

## どこで出てくるか
HDF5は、シミュレーションの出力、実験装置の計測データ、機械学習の学習データなど、分野を問わず広く用いられる。[[netCDF]]の第4版はHDF5をファイル形式の基盤としている。HPCのI/O研究では、アプリケーションが[[POSIX]]や[[MPI-IO]]を直接呼ぶのではなく、HDF5のような高水準ライブラリを介してI/Oを行う場合が多いため、HDF5のチャンク、メタデータの扱い、集団I/Oの設定が、[[Parallel File System|並列ファイルシステム]]上の性能を大きく左右する。ファイルの中身は `h5dump` や `h5ls` で確認できる。クラウドの[[Object Storage|オブジェクトストレージ]]上での利用では、一つのファイルの中を細かく参照する構造が不利となるため、[[Zarr]]などの形式が代替として用いられる。
