# jump

基本ワークフローの「次に書くと良い用語候補」は未作成リンクから選ぶため、既に書いた用語の**隣**しか提案しない。これを続けると vault は書き始めた地点の周りに密に育ち、新メンバーが出会う用語のうち既存の用語から遠い領域は空白のまま残る。このスキルは skip list の上位レベルの skip のように、隣を飛ばした先の用語を、どれも同じくらいの**歩幅**で提案する。距離は文字列の一致ではなく、ノートの内容を読んだうえで意味の上で測る。

## 距離

用語 X から既存の用語 A への距離は、A を理解した新メンバーが X に到達するまでに、間に挟まる概念の数である。

- **隣（歩幅1）**：A の本文が名指ししている用語、A の構成要素・下位概念・直接の対比。例：Lustre に対する MDS、MPI に対する MPI_Allreduce。基本ワークフローが拾うので、jump では提案しない。
- **jump（歩幅2〜3）**：A と X の間に、vault に無い概念が1〜2個挟まる。X のノートを書くときにその中間の概念を本文で一言説明すれば済む距離である。例：既存の Roofline Model から、中間の「性能を左右するパラメータ（ブロックサイズなど）の探索」を飛ばした先の Autotuning。
- **遠すぎる**：中間の概念が3個以上要る、または既存のどの用語ともつながらない。ノートを書いても vault の中で浮くので提案しない。

X の距離は、vault の全用語のうち最も近い用語からの距離で決まる。ある既存用語から遠くても、別の既存用語の隣なら X は隣である。

## jump の条件

候補は次のすべてを満たす。

- **歩幅が揃っている**：すべての候補が jump の距離にあり、最も近い既存の用語と、飛ばした中間の概念を言える。
- **同じ粒度**：既存の用語ノートと同じくらいの一般性である。分野名ほど大きくなく、製品の個別機能ほど小さくもない。
- **新メンバーが出会う**：研究室の分野（`index.md` の各 map）の論文、ミーティング、ツールで実際に出てくる。公開情報で説明でき、出典を示せる。
- **散らばっている**：候補どうしが互いの隣ではなく、最も近い既存の用語もそれぞれ異なる。候補の集合が vault の周りを偏りなく覆う。

## 手順

### 1. 全用語を読む
`index.md` と全 map を読む。用語ノートは map ごとにサブエージェントへ分けて並列に読ませ、各サブエージェントには担当 map に載る用語ノートを**全文**読ませて、次を返させる。

- 各用語が扱う概念の範囲（本文で説明している構成要素・下位概念・対比まで含めて）
- その map の分野のうち、用語ノートの説明がどこにも及んでいない話題

引数で map が指定されていれば、その map の担当分だけを候補探しの対象とする。ただし距離の判定には全 map の結果を使う。

完了条件：全 map について、カバー範囲と空白の報告が揃っている。

### 2. 候補を多めに挙げる
手順1の空白から、必要な数の3倍程度の候補を挙げる。各候補について次を書き出す。

- 最も近い既存の用語と、その間に挟まる中間の概念（歩幅）
- 本文でリンクすることになる既存の用語（2つ以上）

手順1の報告と照らし、既存の用語ノートが既に説明している（aliases や本文の下位概念として含まれている）ものは隣か重複として除く。歩幅が jump の範囲に無いものも除く。

### 3. 歩幅を揃えて選ぶ
残った候補から、上の「jump の条件」に照らして指定の数を選ぶ。選んだ候補を並べ、歩幅が揃っていること、候補どうしが互いの隣でないこと、最も近い既存の用語が重なっていないことを確かめる。内容に確信のない候補は WebSearch で実在と一般的な用法を確かめ、確かめられないものは外す。

### 4. 提案する
選んだ候補ごとに次を示し、ユーザーが選ぶのを待つ。ノートは作らない。

- 用語名（ファイル名にする英語表記と日本語名）と入る map
- 歩幅：`既存の用語 → 中間の概念 → 候補`
- 新メンバーがどこで出会うか（一言）

最後に、手順1で見つけた空白のうち今回の候補で覆えなかったものがあれば一言添える。
