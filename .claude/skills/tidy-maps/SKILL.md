# tidy-maps

map は用語を足すたびに末尾へ追記され、節の分類軸が崩れていく。このスキルは map を**読む順に並んだ目次**へ戻す。map の書式は `CLAUDE.md` の「map のテンプレート」に従う。

## 整った map の条件

点検と組み直しの基準である。各項目は map の全節に適用する。

- **一つの節に一つの分類軸**：節見出しは「この節の項目は何の一種か」に答える。節内のすべての項目が同じ問いに同じ種類の答えを返す。例：「抽象化モデル」節にはモデル（ブロック・ファイル・オブジェクト・KV）だけを置き、B木・LSM木・Bloom Filter のような**データ構造**や、RocksDB・Garnet のような**実装**は別の節に置く。
- **概念→仕組み→実装→道具の順**：節は前提となる概念から先に並べ、具体的な製品・ツール・ベンチマーク・論文を後に置く。節の中も一般的なものから特殊なものへ並べる。
- **節の大きさ**：本編の一節は3〜12項目を目安とする。12を超えたら一つの軸で `###` に分けるか節を割る。1〜2項目の節は隣の節へ合流できないか検討する。
- **一項目一か所**：同じ用語を本編の二つの節に載せない。最も読む順に合う節に一度だけ置く。「まず読む」での再掲は例外とし、その用語は本編のどこかにも載せる。
- **分野の境界**：その map の分野が主題でない用語は、主題の map に置き、こちらには載せないか「（[[Other Map]]を参照）」と添えて一度だけ載せる。データ構造は `Data Structures`、通信は `Network` のように、既存の map を先に探す。
- **frontmatter と一致**：map に載せた用語は、その用語ノートの `maps:` にその map を持つ。逆に `maps:` に map を持つ用語は、その map に載っている。
- **一言説明**：各項目の説明は「— 〜である。」の一文で、用語ノートの一行定義と矛盾しない。節見出しが既に言っていることは繰り返さない。
- **map の大きさ**：本編が60項目を超え、互いにほぼ読み合わない節の塊があれば、新しい map への分割を**提案**する（実行はユーザーの承認後）。

## 手順

### 1. 対象を決める
引数の map を対象とする。引数がなければ全 map を対象とし、次の診断の結果から問題の多い map を優先する。

### 2. 機械的な診断
リポジトリのルートで次を実行する。

```
python3 .claude/skills/tidy-maps/check_maps.py [map名 ...]
```

重複掲載・未作成リンク・frontmatter との不一致・節ごとの項目数を列挙する。出力のすべての行を、後の提案のどこかで扱う。

### 3. 分類軸の診断
対象 map を通読し、載っている各用語ノートの一行定義（`>` の行）と `maps:` を読む。節ごとに「この節の分類軸は何か」を一語で言い、その軸に合わない項目をすべて挙げる。軸を一語で言えない節は、節そのものを作り直す対象とする。

完了条件：対象 map の全項目について「今の節に残す／どこへ移す」が決まっている。

### 4. 再構成案を提示し、承認を得る
map ごとに次を示し、ユーザーの承認を待つ。分類は判断を伴うので、承認前にファイルを編集しない。

- 新しい節立て（見出しと各節の項目名だけの骨子）
- 移動・削除・他 map への移動の一覧と、それぞれの理由（一行）
- frontmatter を直す用語ノートの一覧
- map の新設・分割の提案があればその案

### 5. 適用する
承認された案で map を書き換える。あわせて次を行う。

- 変更した map と用語ノートの `updated` を今日の日付にする（用語ノートは `maps:` を変えたものだけ）。
- 用語ノートの `maps:` を map の掲載と一致させる。
- map を新設・削除したら `index.md` の「分野」を更新する。
- 表の中の表示名付きリンクは `\|` でエスケープする。

### 6. 検証する
`check_maps.py` を再実行し、承認時に残すと決めたもの以外の指摘が消えていることを確かめる。`git diff` で、元の map にあった項目がすべてどこかの map に残っていることを確かめる（意図して外したものを除く）。

### 7. 報告とコミット
変更した map ごとに、節立ての変化と移動した項目数を短く報告する。作業ブランチ上なら map ごとに一つのコミットにまとめる。
