# link-terms

用語ノートは書かれた順に増えるため、先に書いたノートは後から作られた用語にリンクしていない。例えば早くに書いた Lustre のノートは、後から作った InfiniBand や DNE を本文で名指ししているのにリンクしていない。このスキルはその**リンク漏れ**を埋める。向きは二つある。

- **被リンク**：新しい用語 X について、X に言及している既存のノートから X へリンクする。
- **発リンク**：古いノート Y について、Y の本文が言及している後発の用語へリンクする。

## リンクの規則

- 本文（「概要」「どこで出てくるか」など）で、そのノートでの**初出の一か所**だけをリンクにする。同じ用語の二度目以降はリンクしない。
- 既に本文でリンクしているなら何もしない。「関係」の節のリンクは本文のリンクの代わりにならない。
- 「関係」「出典」の節、見出し、インラインコード、URL、そのノート自身の用語は対象外とする。「関係」に行を足すことはしない（逆方向はバックリンクで見える）。
- 表記がファイル名と違えば表示名を使う：`[[Distributed Lock Manager|分散ロックマネージャ]]`。表の中では `|` を `\|` とエスケープする。
- map では、項目の一言説明の中の言及もリンクしてよい。項目の先頭のリンクはそのままにする。

## 判断

候補は文字列の一致で集めるので、同じ綴りの別物が混ざる。各候補について周辺の段落を読み、次を確かめてからリンクする。

- **同じ概念か**：「DNE」は Lustre の Distributed Namespace と NADINO の DPU-enabled Network Engine の二つがある。「名前空間」は NVMe の namespace とは限らない。「カーネル」は Linux カーネルとは限らない（CUDA のカーネル関数）。「Dragonfly」はトポロジとデータストアがある。
- **リンクが読者の助けになるか**：その文の理解にその用語の説明が効くならリンクする。「ファイル」「キャッシュ」「ロック」のような一般語が、特定の概念を指さずに通りがかりで使われているだけならリンクしない。
- **より具体的な用語があるか**：「Lustre のクライアントのキャッシュ」なら Cache より Lustre PCC が適切な場合がある。

## 手順

### 1. 対象を決める
引数があればそれを対象とする（用語名なら被リンク、ノート名なら発リンク）。引数がなければ、このブランチで追加・変更した用語を対象とする。

```
git diff --name-only --diff-filter=AM main...HEAD -- terms/
```

新しく追加した用語は被リンクと発リンクの両方を、変更した用語は発リンクを調べる。

### 2. 候補を集める
リポジトリのルートで次を実行する（全組を出すと30秒程度かかる）。

```
python3 .claude/skills/link-terms/find_unlinked.py [名前 ...]
```

各行は `ノート:行番号  用語  「当たった語」  行の冒頭` である。各ノートで、リンクの無い用語の最初の出現だけを示す。

### 3. 読んで判断し、リンクする
候補ごとに該当ノートの段落を読み、上の「判断」に照らしてリンクするかを決め、Edit でリンクにする。候補の行が初出でない場合（候補は aliases で当たるため、別の表記で先に出ていることがある）は、本文の最初の言及をリンクにする。

完了条件：出力のすべての候補について、リンクしたか、リンクしない理由（別概念・一般語など）が言える。

### 4. 仕上げ
- 編集したノートの `updated` を今日の日付にする。
- `git diff` を読み、リンクの綴り（ファイル名と一致するか）、表の中の `\|`、二重リンクがないことを確かめる。
- 対象を再び `find_unlinked.py` にかけ、残った候補がすべてリンクしないと判断したものであることを確かめる。

### 5. 報告とコミット
リンクを加えたノートの数と主なリンク、見送った候補の種類（例：「名前空間」は NVMe の namespace ではない）を短く報告する。作業ブランチ上なら一つのコミットにまとめる。
