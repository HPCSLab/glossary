# Storage（ストレージ）

> データを永続的に保持し、読み書きを提供する仕組みと、その抽象化の階層を扱う。記憶装置からLinuxのI/Oの経路、ファイルシステムの実装までの、一台の計算機の中のストレージが中心である。複数の計算機で共有するストレージは[[HPC Storage]]で、データベースとキーバリューストアは[[Databases]]で扱う。

## まず読む
- [[File System]] — データをファイルとディレクトリの階層として扱う最も基本的な抽象である。

## ストレージの抽象化モデル
- [[Block Storage]] — 番号で指定する固定長ブロックを読み書きする最下層のモデルである。
- [[File System]] — ブロックの上に名前・階層・[[Metadata|メタデータ]]を構築するモデルである。
- [[Object Storage]] — キーで識別されるオブジェクトを丸ごと格納・取得する、平坦な名前空間のモデルである。代表的なサービスは[[Amazon S3]]である。

## 性能の指標
- [[Latency]] — 要求から完了までの時間であり、小さなI/Oやメタデータ操作の性能を表す。
- [[Bandwidth]] — 単位時間あたりの転送量であり、大きなI/Oの性能を表す。

## 記憶装置とその接続
### 記憶装置
- [[HDD]] — 回転する磁気ディスクに記録する記憶装置であり、ランダムなアクセスが遅い。
- [[SSD]] — NANDフラッシュを用いる記憶装置であり、[[FTL]]とガベージコレクションが性能を左右する。
### SSDの内部
- [[FTL]] — 論理アドレスをフラッシュ上の位置に対応付け、ガベージコレクションとウェアレベリングを行うSSDの内部の層である。
- [[QLC]] — NANDフラッシュのセルに4ビットを記録する方式であり、大容量で安価な代わりに性能と書き換え回数が劣る。
- [[SLC Cache]] — TLCやQLCの一部をSLCとして使う書き込みの受け皿であり、一杯になると書き込みが急に遅くなる。
### 装置の接続
- [[PCIe]] — SSDなどの装置を計算機に接続する規格であり、NVMeはこの上で動作する。
- [[NVMe]] — 多数のキューを持つ、SSDのための論理デバイスインタフェースの規格である。
### バイト単位でアクセスする記憶
- [[Intel Optane Persistent Memory]] — バイト単位で読み書きできる不揮発性のメモリであり、2022年に開発が終了した。
- [[devdax]] — 永続メモリをファイルシステムを介さずにキャラクタデバイスとして直接写像する利用形態である。
- [[CXL]] — CPUからメモリとしてアクセスできる装置を接続する規格であり、記憶階層の新しい層となる。

## ブロック層とボリューム管理
- [[blk-mq]] — CPUごとの複数のキューでI/O要求をドライバへ渡す、Linuxのブロック層の仕組みである。
- [[Device Mapper]] — 表に従ってI/Oを変換する仮想ブロックデバイスを構築する枠組みであり、LVMや暗号化の基盤である。
- [[LVM]] — 物理デバイスを束ね、大きさを変更できる論理ボリュームを切り出す仕組みである。
- [[RAID]] — 複数の装置への分散配置と冗長化によって性能と耐故障性を高める手法である。多数のサーバへの一般化は[[Erasure Coding|消失訂正符号]]（[[HPC Storage]]）である。

## ネットワーク越しのブロックストレージ
- [[iSCSI]] — SCSIのコマンドをTCP/IPで運び、リモートの記憶装置をブロックデバイスとして使う規格である。
- [[NBD]] — リモートのサーバの記憶領域を、TCPでブロックデバイスとして使うLinuxの仕組みである。
- [[NVMe-oF]] — NVMeのコマンドをネットワーク越しに用い、リモートのSSDをローカルに近い性能で使う規格である。
- [[NVMesh]] — 複数サーバのNVMe SSDを束ね、ターゲットのCPUを介さずに共有する製品であり、NVIDIAによる買収の後、製品としての展開は終了した。

## ファイル操作のインタフェース
- [[System Call]] — アプリケーションがカーネルの機能を利用するための基本的なインタフェースである。
- [[POSIX]] — ファイル操作のAPIと意味論を定める標準である。
- [[File Descriptor]] — オープン中のファイルを識別する整数であり、読み書き位置（オフセット）と結び付く。
### 開く・閉じる
- [[open]] — パス名からファイルを開き、ファイルディスクリプタを得る。
- [[close]] — ファイルディスクリプタを解放する。永続化は保証しない。
### 読み書き
- [[read]] — オフセット位置から読み込む。`pread()` は位置を指定する。
- [[write]] — オフセット位置へ書き込む。`pwrite()` は位置を指定する。
- [[lseek]] — オフセットを移動する。ホールとスパースファイルの起点となる。
- [[truncate]] — ファイルサイズを変更する。
- [[fsync]] — データを記憶装置へ書き出し、永続化を待つ。
- [[mmap]] — ファイルを仮想アドレス空間に写像し、メモリとして読み書きする。
- [[Direct IO]] — `O_DIRECT` でページキャッシュを迂回し、利用者のバッファと記憶装置の間で直接転送する。
### 名前とメタデータ
- [[stat]] — メタデータを取得する。
- [[link]] — 既存ファイルに名前を追加する（ハードリンク）。
- [[unlink]] — 名前を削除する。実体は参照がなくなった時点で解放される。
- [[rename]] — 名前を不可分に置き換える。安全な更新の定石に用いる。
### 非同期I/O
- [[io_uring]] — 共有リングバッファで要求と完了を受け渡すLinuxの非同期I/Oインタフェースである。

## カーネル内のファイルI/O
- [[VFS]] — 共通インタフェースと個々のファイルシステム実装をつなぐカーネルの抽象化層である。まずここから読む。
- [[Superblock]] — ファイルシステム全体の管理情報であり、VFSではマウントされたファイルシステム一つを表す。
- [[Inode]] — ファイルの実体とメタデータを表す。名前は持たない。
- [[Dentry]] — パス名の要素とinodeの対応を表し、dcacheとしてパス解決を高速化する。
- [[struct file]] — オープンしたファイルを表し、オフセットとフラグを持つ。ファイルディスクリプタの指す先である。
- [[Page Cache]] — ファイルデータを主記憶に保持するカーネルのキャッシュである。I/O性能と永続化の理解の基礎となる。
- [[address_space]] — ファイルごとのページキャッシュを管理する。
- [[Buffer Head]] — ページの中の一つのディスクブロックの位置と状態を表す古い構造体であり、iomapへの移行が進められている。

## クラッシュ整合性
- [[Crash Consistency]] — 電源断やクラッシュの後もデータ構造が矛盾なく回復できる性質である。
- [[Journaling File System]] — 変更を先にジャーナルに記録し、クラッシュの後に再実行して一貫性を回復する方式である。
- [[JBD2]] — ext4が用いるLinuxのジャーナリング層である。
- [[Copy-on-Write]] — データを上書きせず、変更された部分を新しい場所に書く手法であり、ZFSやbtrfsの基盤である。
- [[Log-Structured File System]] — 全ての更新をログの末尾に追記し、上書きをしないファイルシステムであり、空きを作るクリーニングを要する。
- [[Snapshot]] — ある時点の状態を、データを丸ごと複製せずに保存したものである。

## ローカルファイルシステムの実装
- [[Extent]] — ファイルの論理的な範囲と連続した物理ブロックの範囲の対応を、開始位置と長さで表す記録であり、その数が断片化の度合いを示す。
- [[ext4]] — Linuxの標準的なローカルファイルシステムである。エクステントと遅延割り当てを用いる。
- [[XFS]] — アロケーショングループによって並列なI/Oに強い、RHEL系の標準のファイルシステムである。
- [[btrfs]] — Linuxカーネルに含まれる、コピーオンライトのB木に基づくファイルシステムである。
- [[ZFS]] — ボリューム管理と一体化した、コピーオンライトとチェックサムによる完全性重視のファイルシステムである。
- [[NOVA]] — 永続メモリ向けに、inodeごとのログを持つログ構造のファイルシステムである。

## データの圧縮
- [[LZ4]] — 圧縮率を抑えて圧縮と伸長を非常に速くした可逆圧縮であり、ZFSの透過的な圧縮の既定である。

## カーネルの外での実装
- [[FUSE]] — ファイルシステムをユーザ空間のプロセスとして実装する枠組みである。研究用の試作に多用される。
- [[To FUSE or Not to FUSE]] — FUSEの性能を体系的に測定し、負担が負荷と設定に強く依存することを示したFAST 2017の論文である。
- [[ublk]] — ブロックデバイスをユーザ空間のプロセスとして実装する枠組みである。FUSEより下の層に介入する。
- [[zpoline]] — システムコールを小さな負担で横取りし、ユーザ空間のファイルシステムをアプリケーションから透過的に使わせる仕組みである。
- [[SPDK]] — NVMe SSDをカーネルを経由せず、ユーザ空間からポーリングで直接操作するためのライブラリ群である。

## GPUへのデータ供給
- [[GPUDirect Storage]] — 記憶装置とGPUのメモリの間で、CPUのメモリを経ずに直接データを転送する技術である。
- [[BaM]] — GPUのスレッドがNVMe SSDへの要求を直接発行する、GPU主導のストレージアクセスである。

## 記憶装置上の索引構造
- [[B-Tree]] — 記憶装置上の索引の標準となる平衡木であり、その場で更新する。
- [[B-epsilon Tree]] — B木の内部節点にバッファを持たせ、探索性能を保ちつつ挿入を高速化した索引である。
- [[LSM-Tree]] — 書き込みをまとめて順次書き出し、段階的に併合する索引構造であり、多くのKVSの基盤である。
- [[Full-Path Indexing]] — 完全なパス名をキーとして格納し、部分木の走査を速くする方式である。名前の変更が弱点となる。

## 実験の道具
- [[fio]] — 読み書きの種類と並行度を指定して、記憶装置やファイルシステムの帯域、IOPS、レイテンシを測るベンチマークである。
- [[iostat]] — 装置ごとの要求数、転送量、待ち時間、キュー長を間隔ごとに表示し、装置に実際に届いているI/Oを確かめるコマンドである。
- [[FEMU]] — QEMUを基盤として、SSDの内部構造まで模擬する研究用エミュレータである。
- [[e2fsprogs]] — ext4などを作成・検査・修復・調査する `mke2fs`・`e2fsck`・`debugfs` などのツール群である。
- [[xfstests]] — 変更の前後で多数のテストを実行し、ファイルシステムの機能が壊れていないかを確かめる回帰テストのスイートである。

## 研究成果の発表
- [[FAST]] — ファイルシステムとストレージを専門とする、この分野で最も権威のあるUSENIXの国際会議である。
