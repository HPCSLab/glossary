# Storage（ストレージ）

> データを永続的に保持し、読み書きを提供する仕組みと、その抽象化の階層を扱う。

## まず読む
- [[File System]] — データをファイルとディレクトリの階層として扱う最も基本的な抽象である。

## ストレージの抽象化モデル
- [[Block Storage]] — 番号で指定する固定長ブロックを読み書きする最下層のモデルである。
- [[File System]] — ブロックの上に名前・階層・メタデータを構築するモデルである。
- [[Object Storage]] — キーで識別されるオブジェクトを丸ごと格納・取得するモデルである。

## インタフェースと標準
- [[POSIX]] — ファイル操作のAPIと意味論を定める標準である。
- [[File Descriptor]] — オープン中のファイルを識別する整数であり、読み書き位置（オフセット）と結び付く。
- [[VFS]] — Linuxカーネルにおけるファイルシステムの共通インタフェース層である。

## ファイル操作API
### 開く・閉じる
- [[open]] — パス名からファイルを開き、ファイルディスクリプタを得る。
- [[close]] — ファイルディスクリプタを解放する。永続化は保証しない。
### 読み書き
- [[read]] — オフセット位置から読み込む。`pread()` は位置を指定する。
- [[write]] — オフセット位置へ書き込む。`pwrite()` は位置を指定する。
- [[lseek]] — オフセットを移動する。ホールとスパースファイルの起点となる。
- [[truncate]] — ファイルサイズを変更する。
- [[fsync]] — データを記憶装置へ書き出し、永続化を待つ。
- [[mmap]] — ファイルを仮想アドレス空間に写像し、メモリとして読み書きする。
### 名前とメタデータ
- [[stat]] — メタデータを取得する。
- [[link]] — 既存ファイルに名前を追加する（ハードリンク）。
- [[unlink]] — 名前を削除する。実体は参照がなくなった時点で解放される。
- [[rename]] — 名前を不可分に置き換える。安全な更新の定石に用いる。

## デバイスとブロック層
- [[SSD]] — NANDフラッシュを用いる記憶装置であり、FTLとガベージコレクションが性能を左右する。
- [[NVMe]] — 多数のキューを持つ、SSDのための論理デバイスインタフェースの規格である。
- [[FEMU]] — QEMUを基盤として、SSDの内部構造まで模擬する研究用エミュレータである。
- [[blk-mq]] — CPUごとの複数のキューでI/O要求をドライバへ渡す、Linuxのブロック層の仕組みである。
- [[Device Mapper]] — 表に従ってI/Oを変換する仮想ブロックデバイスを構築する枠組みであり、LVMや暗号化の基盤である。
- [[LVM]] — 物理デバイスを束ね、大きさを変更できる論理ボリュームを切り出す仕組みである。
- [[RAID]] — 複数の装置への分散配置と冗長化によって性能と耐故障性を高める手法である。

## Linux VFS の内部構造
- [[VFS]] — 共通インタフェースと個々のファイルシステム実装をつなぐカーネルの抽象化層である。まずここから読む。
- [[Superblock]] — マウントされたファイルシステム全体を表す。
- [[Inode]] — ファイルの実体とメタデータを表す。名前は持たない。
- [[Dentry]] — パス名の要素とinodeの対応を表し、dcacheとしてパス解決を高速化する。
- [[struct file]] — オープンしたファイルを表し、オフセットとフラグを持つ。ファイルディスクリプタの指す先である。
- [[address_space]] — ファイルごとのページキャッシュを管理する。

## ファイルシステムの実装
- [[ext4]] — Linuxの標準的なローカルファイルシステムである。エクステントと遅延割り当てを用いる。
- [[ZFS]] — ボリューム管理と一体化した、コピーオンライトとチェックサムによる完全性重視のファイルシステムである。
- [[btrfs]] — Linuxカーネルに含まれる、コピーオンライトのB木に基づくファイルシステムである。
- [[JBD2]] — ext4が用いるジャーナリング層であり、クラッシュ時の整合性を保証する。

## I/Oインタフェース
- [[System Call]] — アプリケーションがカーネルの機能を利用するための基本的なインタフェースである。
- [[io_uring]] — 共有リングバッファで要求と完了を受け渡すLinuxの非同期I/Oインタフェースである。

## ユーザ空間での実装
- [[FUSE]] — ファイルシステムをユーザ空間のプロセスとして実装する枠組みである。研究用の試作に多用される。
- [[ublk]] — ブロックデバイスをユーザ空間のプロセスとして実装する枠組みである。FUSEより下の層に介入する。

## 観測と拡張
- [[BPF]] — 検証済みのプログラムをカーネル内で実行する仕組みであり、I/Oの観測やカーネルの拡張に用いる。

## データ形式
- [[HDF5]] — 多次元配列を階層的に格納する形式であり、並列I/Oの性能を左右する（[[Scientific Data]]を参照）。
- [[Zarr]] — チャンクを独立したオブジェクトとして格納する、オブジェクトストレージ向けの配列形式である。

## 性能指標
- [[Bandwidth]] — 単位時間あたりの転送量であり、大きなI/Oの性能を表す。
- [[Latency]] — 要求から完了までの時間であり、小さなI/Oやメタデータ操作の性能を表す。

## キャッシュと永続化
- [[Page Cache]] — ファイルデータを主記憶に保持するカーネルのキャッシュである。I/O性能と永続化の理解の基礎となる。

## 共有・並列化
- [[Distributed File System]] — ネットワーク越しにファイルを共有するファイルシステムである。
- [[Parallel File System]] — 複数のサーバにデータを分散し並列にI/Oを行うファイルシステムである。
- [[Lustre]] — HPCで最も広く用いられる並列ファイルシステムの実装である。
- [[MPI-IO]] — 多数のプロセスが共有ファイルを協調して読み書きするためのインタフェースである（[[Parallel Computing]]を参照）。
- [[Ceph]] — オブジェクト・ブロック・ファイルの三つのインタフェースを提供する分散ストレージである。
- [[Consistency Model]] — 共有データの書き込みがいつ誰に見えるかの規則であり、POSIX・NFS・MPI-IO・S3で異なる。
