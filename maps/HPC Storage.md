# HPC Storage（HPCストレージ）

> 複数の計算機から共有されるストレージ、特にHPCの並列ファイルシステムと並列I/Oの仕組みと評価を扱う。一台の計算機の中のストレージは[[Storage]]で扱う。

## まず読む
- [[Parallel File System]] — 多数のサーバにデータを分散し、多数のクライアントから並列に読み書きさせるファイルシステムである。

## 共有の基礎
- [[Distributed File System]] — ネットワーク越しにファイルを共有するファイルシステムの総称である。
- [[Parallel File System]] — 複数のサーバにデータを分散し並列にI/Oを行うファイルシステムである。
- [[Metadata]] — ファイルの名前・属性・配置の情報であり、その操作の性能がHPCストレージのボトルネックとなりやすい。
- [[Consistency Model]] — 共有データの書き込みがいつ誰に見えるかの規則であり、POSIX・NFS・MPI-IO・S3で異なる。
- [[Distributed Lock Manager]] — 複数のクライアントのキャッシュの一貫性を、ロックで保つ仕組みである。LustreではLDLMと呼ぶ。
- [[Erasure Coding]] — 複製より少ない容量で多数のサーバにまたがる冗長化を行う手法であり、再構築と小さな書き換えの費用が大きい。

## 並列I/O
- [[Access Pattern]] — 位置の順序、一回の大きさ、N-NとN-1などの、I/Oの性能を左右する読み書きの特徴である。
- [[MPI-IO]] — 多数のプロセスが共有ファイルを協調して読み書きするための、MPIの一部のインタフェースである。
- [[Collective IO]] — 細かいI/Oを集約役に集め、少数の大きな読み書きにまとめるMPI-IOの最適化である。
- [[HDF5]] — MPI-IOの上で並列I/Oを行う高水準のライブラリと形式である（[[Scientific Data]]を参照）。

## 共有ファイルシステムと分散ストレージの実装
### Lustreとその派生
- [[Lustre]] — HPCで最も広く用いられる並列ファイルシステムの実装である。
- [[EXAScaler]] — DDNが提供するLustreを基にした商用の並列ファイルシステムであり、[[Pegasus]]や[[Miyabi]]が用いる。
- [[FEFS]] — 富士通がLustreを基に拡張したファイルシステムであり、京と富岳の第2階層で用いられている。
### その他の並列・分散ファイルシステム
- [[NFS]] — 最も広く用いられるネットワークファイルシステムであり、close-to-open一貫性を採る。
- [[IBM Storage Scale]] — 旧称GPFS。メタデータも分散して扱う共有ディスク型の並列ファイルシステムである。
- [[BeeGFS]] — サーバがユーザ空間で動く、HPC向けの並列ファイルシステムである。
- [[Gfarm]] — 多数の計算機のローカルな記憶装置を束ねる分散ファイルシステムであり、HPCI共用ストレージに用いられている。
- [[GFS]] — POSIXの意味論を緩めて追記に最適化した、データセンタ向けの分散ファイルシステムの古典である。
- [[Colossus]] — GFSの後継であり、メタデータをBigtableに置いて規模を拡張したGoogleのファイルシステムである。
### オブジェクトを基本とする分散ストレージ
- [[Ceph]] — オブジェクト・ブロック・ファイルの三つのインタフェースを提供する分散ストレージである。
- [[DAOS]] — カーネルを経由せず[[NVMe]]と[[RDMA]]を直接使う、HPC向けの分散オブジェクトストレージである。
- [[Amazon S3]] — AWSのオブジェクトストレージのサービスであり、そのAPIは多くの製品が互換インタフェースとして提供する事実上の標準である。

## メタデータ性能の拡張
- [[DNE]] — Lustreの名前空間を複数のMDTに分け、メタデータの処理を分散させる機能である。
- [[IndexFS]] — 既存の並列ファイルシステムの上で、メタデータを多数のサーバに分散するミドルウェアである。
- [[SingularFS]] — 永続メモリとRDMAを前提に、単一のメタデータサーバで十億規模のファイルを扱う分散ファイルシステムである。
- [[Full-Path Indexing]] — 完全なパス名をキーとして格納する方式であり、GekkoFSやCHFSはそのハッシュで担当のサーバを決める。

## バーストバッファ
- [[Burst Buffer]] — 並列ファイルシステムの前にSSDの層を置き、短時間に集中するI/Oを受け止める仕組みである。専用のサーバによる構成とノードローカルな構成がある。
- [[DDN IME]] — SSDを束ねた専用のサーバ群で書き込みを受け止め、整列してから並列ファイルシステムへ書き戻す製品である。

## ノードローカルな記憶装置の活用
- [[Node-local Storage]] — 計算ノードに搭載され、そのノードからのみ使える記憶装置とファイルシステムである。
- [[Ad Hoc File System]] — ジョブのノードのローカルな記憶装置を束ねて一時的に構築するファイルシステムの総称である。
- [[GekkoFS]] — ノードローカルな記憶装置を束ねる、ユーザ空間の一時的な分散ファイルシステムである。
- [[CHFS]] — コンシステントハッシュでデータとメタデータを分散させる、ノードローカルな並列キャッシュファイルシステムである。
- [[UnifyFS]] — ジョブの間だけノードローカルな記憶装置に共有の名前空間を提供する、ユーザレベルのファイルシステムである。
- [[LLIO]] — 富岳の第1階層ストレージであり、SSDで第2階層のキャッシュとジョブ用の一時領域を提供する。
- [[Lustre PCC]] — Lustreの名前空間を保ったまま、クライアントのローカルな記憶装置をキャッシュとして用いる機能である。

## ストレージサービスの構築基盤
- [[Mercury]] — 大きなデータをRDMAで転送する、HPC向けのRPCフレームワークである。
- [[Margo]] — Mercuryを基盤にストレージサービスを部品の組み合わせで構築するMochiの中核である。

## I/Oの記録と評価
- [[Darshan]] — アプリケーションのI/Oのアクセスパターンを記録し、要約するツールである。
- [[Recorder]] — I/Oスタックの複数の層の呼び出しを一つずつ記録するトレースのツールである。
- [[IOR]] — 多数のプロセスから並列に読み書きし、ストレージの帯域を測るベンチマークである。
- [[mdtest]] — 並列にファイルの作成・属性取得・削除を行い、メタデータ性能を測るベンチマークである。
- [[IO500]] — IORとmdtestを組み合わせたストレージの性能の一覧である。
